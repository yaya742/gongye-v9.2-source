# 试用数据一次性迁移工具

`migrate-pilot-data.mjs` 是供维护者审阅管理员导出副本的一次性工具。它不会连接网站，也不会自动寻找数据文件。**默认只读分析；`--apply` 只改 `--file` 指定的普通文件。**不要把正在运行的服务文件、`server/data/`、`db.json`、`allowlist.txt`、符号链接或硬链接作为输入。

## 使用步骤

先按维护者的安全导出流程取得一致的 JSON 副本，放在受限的独立目录中。不要通过普通用户接口导出数据。先查看分析报告：

```bash
node server/migrate-pilot-data.mjs --file /secure/pilot-export.json
```

只有在报告的 `applyAllowed` 为 `true`、`blockers` 为空，并由管理员审阅合并圈、邀请码和固定帖子状态后，才对这份**导出副本**执行：

```bash
node server/migrate-pilot-data.mjs --file /secure/pilot-export.json --apply
```

工具会在同目录创建 `pilot-export.json.backup-<时间戳>`，核对备份内容与分析输入一致，然后将迁移后的 JSON 写入临时文件并原子替换导出副本。备份名冲突、输入在处理期间变化、结构检查失败或任何无损性检查失败时，工具拒绝替换。保留原导出、迁移后文件、备份和报告供复核；工具不会把迁移结果发布到线上。

## 处理范围与合并规则

- 对每门课仅在发现多个圈时合并；规范圈依次按“活跃圈优先、已知首选圈 ID、较早创建时间、字典序 ID”确定。若存在活跃圈，结果状态为活跃；否则有归档圈时结果为归档。置顶帖子或创建者冲突、未知圈字段、跨课程邀请码冲突等情况会阻止写入。
- 把旧圈的 `circleId` 引用重映射到规范圈；受影响的成员关系按应用已有状态、标记和时间规则合并。帖子、附件和评论的记录数量与字段会逐项核对，除 `circleId` 重映射外不允许变化。原有邀请码和圈内旧邀请码映射保留为规范圈别名；任何邀请码无法唯一回到原课程时拒绝写入。
- 仅当 `p_derivative_draft` 的标题和正文标记都匹配已知固定样例，且状态为 `published` 时，才将其状态改为 `draft`。帖子、附件与评论本身仍保留。ID 对应内容不匹配时只报告并保留原状态。
- 其他圈、用户、资料、帖子状态、附件、评论和应用数据不属于迁移目标。不能确认字段安全保留时只给 dry-run 报告，不允许 `--apply`。

### 重新部署时的源码演示帖子清理

本仓库的 `server/pilot.mjs` 在首次读取旧 JSON 数据文件时，会另行运行一次 `demoPostCleanup` 迁移。它只对已确认的 16 个固定样例 ID 做精确匹配（标题及正文标记也必须相符），并调用应用的永久移除规则：帖子停止公开、关联附件失效、资料退出索引、符合条件的赠签退款。匹配不唯一、文案不同或缺少可执行移除的活跃账号时会跳过；其他帖子保留。新建种子会在返回前处理其中的固定样例；旧版单独存在的导数草稿也只有内容标记完全吻合才会处理。

迁移前服务会在配置的数据文件同目录创建 `*.pre-demo-post-cleanup-v1-*.bak`，并核对备份与原文件逐字节一致后才写入。日志会报告处理数量和备份路径。此行为只适用于部署本仓库的 JSON 试用后端；外部托管平台的数据库不由该代码自动修改。回滚前先停止服务，再将日志中的备份按维护流程恢复到 `DATA_FILE`。

这项迁移只改 JSON 记录，不迁移或校验 PDF 文件本身。当前仓库的试用后端只允许下载三份内置演示 PDF；旧附件记录即使原样保留，若 `path` 不是这三条内置路径，发布后的当前后端也会隐藏下载入口。部署前必须由维护者确认实际附件存储与当前运行代码兼容；如果线上已有真实文件上传或私有存储，先实现对应的受控下载流程，不能直接部署这份试用后端代码。

## 回滚与风险

迁移前先保留原始导出副本。若需撤销对导出副本的修改，确认文件路径后，在同一目录把输出备份原子替换回去，例如：

```bash
BACKUP_PATH=/secure/pilot-export.json.backup-REPLACE_WITH_REPORTED_TIMESTAMP
cp -p -- "$BACKUP_PATH" /secure/pilot-export.rollback.json
mv -f -- /secure/pilot-export.rollback.json /secure/pilot-export.json
```

把 `BACKUP_PATH` 替换成 `--apply` 报告中返回的实际备份路径。

若迁移结果之后被管理员部署到其他环境，回滚必须先停写并确认该环境实际使用的数据路径，再通过该环境的受控恢复流程恢复备份；不要直接覆盖正在运行的数据文件。运行中的外部进程仍可能在最后一次文件检查后写入，因此管理员必须先保证导出副本静止，线上发布与恢复由独立维护流程执行。

这是保守工具，不会识别硬链接以外的所有副本关系，也不能判断导出是否完整或最新。路径保护无法证明用户指定的文件一定来自安全导出；操作者仍需核验来源、权限和版本。遇到 blocker 时应人工审阅数据模型并另拟迁移方案，不要删改 blocker 来强行写入。
